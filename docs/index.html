v6.0.0 zsh · bash · fish: release notes

Your shell setup, managed by commands.

PATH entries, aliases, env vars, encrypted secrets, scripts and plugins — added with one command each, compiled into one file your shell sources at startup.

$ brew tap dvrd/wayu
$ brew install wayu
$ wayu init
$ git clone https://github.com/dvrd/wayu && cd wayu
$ odin build build -out:build_it && ./build_it install
# builds, installs to ~/.local/bin, runs wayu init

wayu init offers to add one line to your rc file Read the quickstart →

  • MIT licensed
  • zsh · bash · fish
  • One binary, no runtime dependencies
  • 676 unit tests + end-to-end suites
  • Stable from 7.0 on

What each command writes into core.zsh

How core.zsh is built →

The dir is stored with a key in entries.json; open shells re-apply the list at their next prompt from path_sync.zsh.

Constants are exported first, in order; aliases come last, after plugins, so yours win.

No value in core.zsh: it sources a per-session cache and calls wayu secrets cache only when secrets.json changed.

Loaders are regenerated from plugins.json; with defer_plugins = true they load after the first prompt.

The branch comes from .git/HEAD without running git. fish gets the same prompt in core.fish.

What it replaces

Eleven jobs, one binary.

Each card is something you used to do by hand in an rc file, or with another tool. In wayu it is a command, and the result lands in the same generated init.

replaces export PATH="…:$PATH" in each rc file

PATH entries

Keyed, validated, deduplicated. Open shells pick up a change at their next prompt.

wayu path add ~/.cargo/bin

replaces alias and export blocks

Aliases & constants

Constants expand $VAR; values that look like credentials are masked in every list.

wayu alias add gs 'git status -sb'

replaces API keys in plaintext .env files and dotfiles

Encrypted secrets

ChaCha20-Poly1305, master key in the macOS Keychain, the Secret Service or a 0600 file. Value read with hidden input; config, generated files and backups only hold the name. Run-only secrets reach one command through wayu secrets run.

wayu const add OPENAI_API_KEY --secret

replaces a hand-kept ~/bin

Scripts, any language

Swift, Python, Ruby, Node, Bun, shells, Perl, Lua. Swift is compiled; the rest are linked into a dir on PATH.

wayu script new today --lang python

replaces a separate plugin manager

Plugins

From a built-in registry or a git URL. Enable, disable, load priority, dependencies, conflict checks. Two of the usual ones are built in (below).

wayu plugin add autosuggestions

replaces a prompt framework (zsh, fish)

Native prompt

Opt-in, for zsh and fish. Git branch read from .git/HEAD without running git, project contexts, async right prompt, vi-mode.

[prompt] enabled = true

replaces eval "$(tool init zsh)" on every start

Tool loaders

Init output cached until the binary changes; nvm, conda and sdkman load on first call.

zoxide = { kind = "evalcache", args = "init zsh" }

replaces installer lines piling up at the end of .zshrc

wayu optimize

Moves source <(tool completion zsh), eval "$(… init zsh)", fpath edits, a second compinit, PATH exports and aliases from your rc file into wayu's cached init. Shows the diff first, backs the file up, and an open shell tells you when new lines appear.

wayu optimize --dry-run

replaces zsh-autosuggestions and zsh-syntax-highlighting

Suggestions & highlighting zsh

Opt-in and built into core.zsh: fish-like suggestions from history, and command-line highlighting with zsh-syntax-highlighting's style names, using zsh's own lexer. One zle-line-pre-redraw hook, no widgets re-wrapped before every prompt, no forks; a keystroke re-highlights only the last words. With them on, the two plugins are not loaded.

[settings] autosuggest = true · highlight = true

replaces functions pasted into .zshrc

Functions

One file per function, a skeleton opened in $EDITOR, sourced at startup.

wayu function add mkcd

replaces bisecting .zshrc to find what broke

Doctor

Checks PATH, config, scripts, plugins, backups, secrets and slow startup lines. Exits 78 on errors, so CI can gate on it.

wayu doctor --fix --dry-run

Encrypted secrets

          
API keys out of your dotfiles.

          
A secret is a constant whose value is encrypted at rest. Your config, the generated shell code and the backups hold only its name; the key sits in your OS keystore.

        

        
    
          
  1. 
            
    01 · Add
    
            
    Typed once, never echoed
    
            
    The value is read with hidden input, so it stays out of ps and your shell history.
    
            
    
              
    zsh
    

    ❯ wayu const add OPENAI_API_KEY --secret
Value for OPENAI_API_KEY (input hidden):
✓ Secret added (encrypted): OPENAI_API_KEY
    
            
    
          
    2. 
          
  2. 
            
    02 · Store
    
            
    Encrypted in secrets.json
    
            
    ChaCha20-Poly1305 under a 256-bit master key, a random nonce per value and the name as associated data. The file is 0600; entries.json keeps only the name.
    
            
    
              
    ~/.local/share/wayu
    

    # entries.json
{"name": "OPENAI_API_KEY", "secret": true}

# secrets.json
"cipher": "chacha20poly1305",
"values": {
  "OPENAI_API_KEY": "y12EtDqRw8ZHkB17hRRR…"
}
    
            
    
          
    3. 
          
  3. 
            
    03 · Use
    
            
    Loaded at shell start, or for one command
    
            
    New shells export it from a per-session cache, decrypted once. A --run-only secret is never exported: wayu secrets run hands it to one command, without a shell.
    
            
    
              
    zsh · a new shell
    

    ❯ echo ${#OPENAI_API_KEY} chars
27 chars
❯ echo ${GH_TOKEN:-not set in this shell}
not set in this shell
❯ wayu secrets run GH_TOKEN -- sh -c 'echo ${#GH_TOKEN} chars'
18 chars

Where the key lives

            
[secrets] backend = "auto" picks the first that fits. Each data dir has its own key; wayu secrets rekey replaces it and re-encrypts everything.

          

          
    
            
  • 
              
    macOS · default
    
              
    Keychain
    
              
    Login keychain, service wayu-master-key. Stored with /usr/bin/security -i over stdin: the key is never on a command line.
    
            
    • 
            
  • 
              
    Linux · with secret-tool
    
              
    Secret Service
    
              
    The freedesktop Secret Service (GNOME Keyring and friends), through secret-tool from a system dir, never looked up in PATH.
    
            
    • 
            
  • 
              
    Anywhere · fallback
    
              
    Key file
    
              
    ~/.config/wayu/secret.key, 0600, refused if others can read it. Keep it out of your dotfiles repo.
    
            
    • 
          

          
The session cache is plaintext in a 0700 dir you own ($XDG_RUNTIME_DIR or $TMPDIR); any change to secrets.json and wayu secrets lock delete it. Five session secrets add about 0.6 ms to startup. How secrets work →

Off by default. Generated into the same core.zsh or core.fish: the git branch comes from .git/HEAD, the changed-file count from an async right prompt, and vi-mode shows its mode in the prompt character.

Hooks around every write

              
Run a command before or after a PATH, alias, constant, plugin or export operation. Placeholders become quoted variables, never code; pre-hooks run only when something will change, none under --dry-run.

              hooks.conf reference →
            

            
          

          

            

              
A token for one command, not your whole shell

              
A run-only secret is never exported. wayu secrets run decrypts it into the environment of that one command and execs it, without a shell. Put it behind an alias and gh gets its token every time.

              [secrets] reference →
            

            
          

          

            

              
Small tools, already on PATH

              
script new writes a skeleton with the interpreter's absolute path as the shebang, opens $EDITOR, and links it into bin/, first among wayu's PATH entries. script import adopts what you already have in ~/bin.

Scriptable by default

              
The CLI never prompts. Lists, search and doctor print JSON with --json; exit codes follow sysexits.h; destructive actions need --yes; --dry-run previews any write.

One health check for the whole setup

              
PATH entries, config, scripts, plugins, backups, the secrets store and key, and startup-file lines that cost time. --fix repairs what it can; any error exits 78.

Questions

          
Before you hand it your shell.

          
Anything else: the docs, or an issue on GitHub.

        

        

          

            What does it change in my rc file, and how do I undo it?
            

              
wayu init asks before it adds one source line to your rc file (it only prints the line when it isn't run in a terminal). Everything else lives in ~/.config/wayu and ~/.local/share/wayu.

              
Every write is backed up first, keeping the newest five per file: wayu backup list, then wayu backup restore entries --yes (or .zshrc, toml). To uninstall, restore your rc file if optimize changed it, remove the line, brew uninstall wayu, and delete those two directories; if you stored secrets, also delete the wayu-master-key item from your keychain.

            

          

          

            Can I keep oh-my-zsh, or my existing .zshrc?
            

              
Yes. wayu init offers to add one line to your rc file and wayu leaves the rest alone, so oh-my-zsh, a plugin manager or your own lines keep running; move things over at your own pace. wayu optimize --dry-run lists the lines after wayu's that it could take over, without changing anything.

            

          

          

            What exactly does wayu optimize touch?
            

              
Only top-level lines that come after the line that loads wayu, in your shell's startup files: eval "$(tool init zsh)" and source <(tool completion zsh) (cached instead), fpath edits, an extra compinit, PATH exports, aliases and exports. Anything inside if, loops, functions or here-documents stays. It prints a diff and exits without --yes; with it, the file is backed up and rewritten atomically. Full rules →

            

          

          

            Where are my secrets and the key?
            

              
Values are encrypted in ~/.local/share/wayu/secrets.json (0600). The master key is in the macOS Keychain, the freedesktop Secret Service on Linux with secret-tool, or ~/.config/wayu/secret.key. Decrypted values go only to a per-session cache in a 0700 dir you own, never to core.zsh, backups or logs. How it works ↑

            

          

          

            Which platforms and shells?
            

              
Prebuilt binaries for macOS 15 or later on Apple silicon (arm64) and Linux on x86_64 (amd64), through Homebrew. There is no prebuilt binary for Intel Macs or Linux on arm64: build those from source with Odin. Tested with zsh 5.9, bash 3.2 and 5.x, fish 4.x, on macOS 15, 26 and 27 and Ubuntu 24.04. Windows is not supported.

            

          

          

            Does it slow down shell startup?
            

              
It is usually faster than what it replaces: everything is precomputed into one core.zsh (zcompiled), tool init output is cached until the binary changes, and plugins can load after the first prompt. See the benchmark, or run wayu build profile on your own setup.

            

          

          

            Will an upgrade break my setup?
            

              
From 7.0 on, the commands, flags, exit codes, --json shapes, wayu.toml keys and data files are stable within a major version. A release that changes a data format or moves a file migrates yours automatically (backup first), and anything being removed is deprecated for at least one minor release first. Stability guarantees →

            

          

          

            How do I report a security problem?
            

              
Privately, through GitHub's Report a vulnerability, not in a public issue. Fixes ship in a patch release of the latest major. Security policy →
